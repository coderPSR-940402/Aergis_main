- README and capability matrix disclose accessibility node-tree retrieval and
  optional local camera-image diagnostic recordings. The existing service
  capability and navigation behavior remain unchanged.
- Development status describes current DevLoop integration and the actual
  inspected repository rules, retaining device acceptance as a separate gate.
- `tools/verify_apk.py` now requires one intact pinned gesture model and one
  intact pinned face model for current APK CLI verification. Both assets are
  checked for missing/duplicate entries, size and SHA-256.
- Production builds use the current verifier. Only integrated sources whose
  Gradle configuration does not declare the face model select the explicit
  `--legacy-gesture-only` contract. Sources with Gaze Lab require both models,

  `verify_model` interface and ephemeral signing fixture remain compatible.
  The signing job itself still independently verifies only the gesture asset;
  the current-source unsigned build gate verifies both. Extending the isolated
  signing contract requires a separate provenance-aware rollback design.

## Remaining dependency verification

No `gradle/verification-metadata.xml` is tracked in the inspected base.
The existing manual **Prepare dependency verification metadata** workflow can
generate a candidate using all current CI tasks:

1. Run the workflow from the reviewed branch in GitHub Actions.
2. Download `dependency-verification-candidate-<commit>` and review the actual
   `gradle/verification-metadata.xml` against trusted upstream artifacts.
3. Commit the reviewed metadata; keep generation out of ordinary CI runs.
4. Run `./gradlew test :app:lint :app:assembleDebug :app:assembleRelease` using
   the metadata. In a disposable copy, change a pinned artifact checksum and
   confirm strict dependency verification rejects that artifact.

The available connector cannot dispatch this workflow, and local dependency
resolution is blocked. No trusted dependency checksums have been fabricated.

## Exact-APK device acceptance

Use the final candidate's source SHA, CI run, version code and APK checksum.
Install over a compatible preview without clearing settings. Record labelled
attempts and actual target activation, not just accessibility callbacks:

- At least 20 ordinary and 20 edge-on deliberate thumb-middle contacts; record
  successful target activations, misses and extras separately.
- Hold each contact: one tap only; release and recontact: a fresh tap. Cover
  short contacts and overlay lag without allowing a moved-target delayed tap.
- Verify mapped long press and mapped precision drag start/move/release as
  separate actions. Back/Home must remain an escape route during dragging.
- Repeat pointer-off highlighted selection and mapped navigation, each input
  channel disabled independently, and disarmed/protected/unknown contexts.
- Exercise hand loss, second hand, camera stall, rotation, pause/resume and
  service restart. Record unexpected actions; do not promote acceptance when
  any safety scenario produces an unexplained action.
- Compare camera delivery age, inference time, publication age and sustained
  thermal behavior under comparable conditions. Publication age is not measured
  display latency. Keep optional Gaze Lab results separate from hand-control
  acceptance and retain a known device-accepted APK for rollback.

## Review and rollback

Independent review identified that invoking a historical verifier could skip
the face check for post-Gaze sources predating this patch. Regression tests
first reproduced that gap; the current-verifier plus explicit pre-Gaze mode
corrects it. The legacy CLI path also has an acceptance test.

Review all changed files and `git diff --check` before committing. This patch
changes documentation and build-time verification, not Android runtime code.
After commit, reverting that commit restores the prior verifier/workflow/docs;
no app settings migration, signing change or baseline movement is involved.
